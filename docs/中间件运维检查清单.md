# 中间件与工程化补齐清单

这个清单专门回答：“除了 Redis，其他组件有没有只是配了依赖，还缺少演示、排查、文档或可靠性设计？”

## 1. 当前结论

| 组件 | 当前状态 | 是否还只是配置 | 说明 |
| --- | --- | --- | --- |
| Redis | 已补齐 | 否 | 有业务 key、AOF 持久化、库存同步、热门排行、运维接口、说明文档 |
| Redisson | 基本够用 | 否 | 依赖 Redis，不需要单独服务；代码中已用于用户预约锁和订单取消锁 |
| RabbitMQ | 已补齐 | 否 | 已有交换机、主队列、死信队列、发布确认、消费重试、积压查询接口 |
| MySQL | 基本够用 | 否 | 有 schema、初始化数据、唯一索引、条件更新、Docker 数据卷 |
| Swagger | 已补齐 | 否 | Controller 注解 + OpenAPI 配置 + Swagger UI |
| Actuator + Prometheus | 已升级 | 否 | 已开放 health、info、metrics、prometheus，并通过 Micrometer 暴露业务指标 |
| Docker Compose | 基本够用 | 否 | 编排 MySQL、Redis、RabbitMQ、应用，并配置健康检查依赖 |
| JMeter | 半完成 | 不是配置问题 | 有压测脚本和报告模板，但本机没安装 JMeter，未生成真实 HTML 报告 |
| 单元测试 | 已升级 | 否 | 覆盖返回结构、密码、推荐、MQ 运维视图、参数校验；已新增 Testcontainers 集成测试类 |

## 5. 还可以继续升级的点

这些不是当前必须，但可以作为面试中主动说的“后续优化方向”：

1. RabbitMQ 加 outbox 本地消息表，保证业务事务和消息投递最终一致。
2. Redis 运维接口里的 key 统计从 `keys` 换成 `scan`，更贴近生产规范。
3. Testcontainers 已接入 MySQL、Redis、RabbitMQ 集成测试类；若本机 Docker API 可被识别，可直接运行真实容器集成测试。
4. 装好 JMeter 后生成真实 `result.jtl` 和 HTML 压测报告。
5. 给 Docker app 容器增加基于 `/actuator/health` 的应用级 healthcheck。
6. 增加前端页面，让注册、预约、候补、看板、运维演示能直接点出来。
