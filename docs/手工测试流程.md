## 新增组件验证：2026-05-17

这部分用于验证本次新增的 Caffeine + Redis、Prometheus/Grafana、Flyway、Testcontainers、Spring Security + JWT。

### A. Spring Security + JWT

1. 打开 `http://localhost:8081/swagger-ui.html`。
2. 调用 `POST /auth/login`。
3. 复制返回的 `data.token`，这个 token 现在是 JWT 格式，通常由三段组成：`header.payload.signature`。
4. 点击 Swagger 右上角 `Authorize`，填入 token。
5. 调用任意需要登录的接口，例如 `GET /reservations?limit=50`。
6. 预期：携带 token 返回正常；不携带 token 返回 401。

### B. Caffeine + Redis 二级缓存

1. 登录管理员账号。
2. 调用 `GET /rooms?limit=100` 或前端进入“教室管理”。
3. 连续调用 `GET /ops/redis/overview`。
4. 观察返回里的 `data.localCache.hitCount`、`missCount`、`hitRate`。
5. 预期：第一次访问可能 miss，重复访问后 hitCount 增加。
6. 修改或新增教室后，再查 `GET /ops/redis/overview`，预期相关教室列表/推荐缓存会被清理后重新生成。

### C. Prometheus + Grafana

1. 启动中间件：

```powershell
docker compose -f docker-compose.middleware.yml up -d
```

2. 启动 Spring Boot 应用。
3. 访问 `http://localhost:8081/actuator/prometheus`，确认能看到指标文本。
4. 访问 `http://localhost:9090/targets`，确认 `classroom-reservation-local` 为 UP。
5. 访问 `http://localhost:3000/`，账号 `admin/admin`。
6. 在 Grafana Explore 中选择 Prometheus，查询：

```text
crs_outbox_pending
crs_audit_recent_requests
http_server_requests_seconds_count
```

### D. Flyway

1. 确认 `src/main/resources/application.yml` 中 `spring.sql.init.mode=never`，`spring.flyway.enabled=true`。
2. 首次启动应用后，MySQL 中应出现 `flyway_schema_history` 表。
3. 预期：`V1__init_schema.sql` 和 `V2__seed_data.sql` 都有执行记录。

### E. Testcontainers

执行：

```powershell
& "D:\java\softwareSpace\IntelliJ IDEA 2026.1.2\plugins\maven\lib\maven3\bin\mvn.cmd" test
```

预期：

1. 普通单元测试通过。
2. 如果 Docker API 可被 Testcontainers 识别，`InfrastructureTestcontainersTest` 会拉起 MySQL/Redis/RabbitMQ 并执行。
3. 如果 Docker API 不可用，该测试会被跳过，不影响普通测试结果。

### 4.10.3 候补过期清理

规则：

```text
reserve_date < 今天
或者 reserve_date = 今天 且 time_slot 开始时间 <= 当前时间
```

触发方式：

```text
1. 定时任务每 60 秒扫描一次。
2. 打开 /reservations/waitlist 或 /reservations/dashboard 时也会顺手清理。
3. 取消预约触发候补补位前会先清理过期候补，避免过期候补被补位。
```

快速验证方式：

```sql
update tb_reserve_waitlist
set reserve_date = date_sub(curdate(), interval 1 day), status = 0
where id = {waitlistId};
```

然后调用：

```text
GET /reservations/waitlist
```

预期：

```text
该候补 status = 4
waitingCount 不再统计它
通知中心出现“候补已过期”
```

### 6.5 智能推荐接口也要校验日期和时间段

规则：日期不能早于今天；如果日期是今天，时间段开始时间必须晚于当前时间。也就是说，今天后面尚未开始的教室时间段可以预约和推荐，已经开始或过去的时间段不能再预约。

接口：

```text
POST /advisor/recommend
```

请求体：

```json
{
  "reserveDate": "2026-06-01",
  "timeSlot": "19:00-21:00",
  "expectedCapacity": 30,
  "buildingName": "计算机楼"
}
```

预期：

```json
{
  "success": false,
  "message": "预约时间段必须符合 HH:mm-HH:mm，且在 08:00-20:00 内",
  "data": null
```

## 8. 常见问题

### Swagger 里没有 token 输入框

使用右上角：

```text
Authorize
```

填入 `X-Token`。全局授权后，普通接口页面不一定显示 token 输入框，这是正常的。

### submit-token 页面没有 Try it out

如果已经点过 `Try it out`，按钮会变成：

```text
Cancel
Execute
Clear
```

此时直接点 `Execute` 就能再次创建令牌。不要点 `Cancel`，除非你想退出执行模式。

### 预约接口必须带两个 token

```text
X-Token: 登录 token
X-Submit-Token: /reservations/submit-token 返回的 data
```

少任意一个都会失败。

### 重复预约返回失败是正常的

同一用户同一时间段只能预约一个教室，所以重复提交返回：

```text
同一用户同一时间段只能预约一个教室
```

这是预期结果，不是系统异常。
## 9. room_slot 名额模型回归测试

本节用于验证 2026-05-17 的业务重构：学生预约的是教室时段名额，不是整间教室。

### 9.1 测试目标

```text
1. 同一个 room_slot 可以被多个学生预约。
2. 成功预约数不能超过教室容量或管理员设置的 slot 容量。
3. 同一学生同一时间段仍然只能预约一个教室。
4. Redis stock、Redis users set、Redis user-time 标记与 MySQL 库存保持一致。
5. 取消预约后库存释放，并可触发候补补位。
```

### 9.2 Swagger 手工测试

1. 登录学生 A，复制 `data.token`。
2. 点击 `Authorize`，填写 `X-Token`。
3. 调用 `POST /reservations/submit-token`，复制返回的 `data`。
4. 调用 `POST /reservations`，Header 填 `X-Submit-Token`。

请求体示例：

```json
{
  "roomId": 1,
  "reserveDate": "2026-06-10",
  "timeSlot": "18:00-20:00",
  "joinWaitlist": true
}
```

5. 换学生 B 登录，重复 1 到 4 步，使用相同 `roomId + reserveDate + timeSlot`。
6. 预期：学生 B 也能预约成功，说明不是“一人占整间教室”。

### 9.3 Redis/MySQL 对账

调用：

```text
GET /ops/redis/stock?roomId=1&reserveDate=2026-06-10&timeSlot=18:00-20:00
```

重点看：

```text
redisStock
reservedUsers
mysqlAvailableCapacity
mysqlTotalCapacity
```

预期：

```text
mysqlTotalCapacity = 教室容量
reservedUsers 包含已预约用户
redisStock 与 mysqlAvailableCapacity 接近或一致
```

### 9.4 同一学生同时间段冲突测试

同一学生先预约：

```text
roomId=1, reserveDate=2026-06-10, timeSlot=18:00-20:00
```

再预约：

```text
roomId=2, reserveDate=2026-06-10, timeSlot=18:00-20:00
```

预期失败：

```text
同一用户同一时间段只能预约一个教室
```

### 9.5 压测验证建议

设置某个 slot 容量为 80，使用 JMeter 1000 用户并发预约同一个 slot。压测后检查：

```sql
SELECT COUNT(1)
FROM tb_reserve_order
WHERE room_id = 1
  AND reserve_date = '2026-06-10'
  AND time_slot = '18:00-20:00'
  AND status IN (0, 1, 4);
```

成功数必须小于等于 80，并且：

```sql
SELECT total_capacity, reserved_count, available_capacity
FROM tb_room_slot
WHERE room_id = 1
  AND reserve_date = '2026-06-10'
  AND time_slot = '18:00-20:00';
```

满足：

```text
reserved_count + available_capacity = total_capacity
```
