# 前端联调测试流程

本文档记录前端页面与 Spring Boot 后端的端到端测试步骤。以后新增页面或功能时，把测试步骤、测试数据和预期结果追加到这里。

## 访问入口

启动后端后访问：

```text
http://localhost:8081/
```

如果后端没有重新构建静态资源，也可以临时打开：

```text
D:\A_project\crs\ClassroomReservationBoot\src\main\resources\static\index.html
```

临时打开本地 HTML 时，页面会自动请求：

```text
http://localhost:8081
```

如果想用临时静态服务预览新版页面：

```powershell
cd D:\A_project\crs\ClassroomReservationBoot\src\main\resources\static
python -m http.server 8090
```

然后访问：

```text
http://localhost:8090/index.html
```

页面会自动把接口请求转发到 `http://localhost:8081`。

## 页面视觉和权限检查点

新版前端按登录入口和角色工作台拆分：

- 登录页 `#/login` 和注册页 `#/register` 是两个独立页面，均不显示顶部栏和左侧导航。
- 登录/注册页使用 `static/assets/oracle-style-bg.png`、`static/assets/console-bg.png` 做企业级大图背景，整体参考 Oracle 风格的黑、白、红视觉体系。
- 未登录时访问任意后台路由会自动回到 `#/login`。
- 登录成功后进入 `#/dashboard`，退出登录后回到 `#/login`。
- 学生端菜单：控制台、预约教室、智能推荐、我的预约、问题反馈、通知中心。
- 管理员端菜单：控制台、教室管理、预约总览、中间件运维、问题反馈、通知中心、联调日志。
- 后台不再出现“登录/注册”菜单。
- 管理员接口不只是在前端隐藏，后端也通过 `@RequireRole("ADMIN")` 限制了教室新增/编辑、Redis 运维、RabbitMQ 运维接口。
- 同一时间只显示当前菜单对应的业务页面，不再把所有模块堆在同一个长页面。
- 移动端点击左上角菜单按钮可以展开或收起侧边栏。

如果页面还是旧样式，优先按 `Ctrl + F5` 强制刷新；如果仍不生效，重启 Spring Boot 或用上面的 `8090` 静态服务预览。

## 核心联调链路

### 1. 登录与角色菜单

页面路由：`#/login`

输入：

```json
{
  "phone": "17715993804",
  "password": "123456"
}
```

预期：

- 登录页不显示左侧导航。
- 学生账号登录后进入 `#/dashboard`。
- 左侧只显示学生端菜单：控制台、预约教室、智能推荐、我的预约、问题反馈、通知中心。
- 学生端不会显示教室管理、中间件运维、联调日志。

管理员输入：

```json
{
  "phone": "19901541686",
  "password": "123456"
}
```

管理员预期：

- 管理员账号登录后进入 `#/dashboard`。
- 左侧只显示管理员端菜单：控制台、教室管理、预约总览、中间件运维、问题反馈、通知中心、联调日志。
- 管理员端不会显示预约教室、智能推荐、我的预约。
- 登录后后台不显示登录/注册菜单。

后端接口：

```text
POST /auth/login
GET /rooms
GET /reservations
GET /reservations/dashboard
GET /notifications
GET /ops/redis/overview    ADMIN only
GET /ops/mq/overview       ADMIN only
```

### 2. 注册校验

页面路由：`#/register`

异常输入：

```json
{
  "phone": "123",
  "password": "123456"
}
```

预期：

- 前端直接提示手机号格式不正确。
- 不发起注册请求。

正常输入：

```json
{
  "username": "demo-user",
  "phone": "18812345678",
  "password": "123456"
}
```

预期：

- 注册成功。
- 自动跳回 `#/login`。
- 登录表单自动回填手机号和密码。
- 注册账号默认为 `USER`，不能看到管理员菜单。

后端接口：

```text
POST /auth/register
```

### 3. 未登录与越权校验

未登录访问：

```text
http://localhost:8081/#/reserve
http://localhost:8081/#/rooms
http://localhost:8081/#/ops
```

预期：

- 自动回到 `#/login`。
- 页面不显示顶部栏和左侧导航。

学生账号登录后手动访问：

```text
http://localhost:8081/#/rooms
http://localhost:8081/#/ops
http://localhost:8081/#/logs
```

预期：

- 前端自动回到 `#/dashboard`。
- 学生菜单不出现管理员入口。
- 手动请求 `POST /rooms`、`PUT /rooms/{id}`、`GET /ops/redis/overview`、`GET /ops/mq/overview` 返回 403。

### 4. 智能推荐

页面区域：智能推荐

输入：

```json
{
  "reserveDate": "今天或之后；如果是今天，时间段开始时间必须晚于当前时间",
  "timeSlot": "18:00-20:00",
  "expectedCapacity": 30
}
```

预期：

- 返回推荐教室列表。
- 点击“选择该教室”后，预约表单自动回填教室、日期和时间段。

后端接口：

```text
POST /advisor/recommend
```

### 5. 预约

页面区域：预约提交

步骤：

1. 选择教室。
2. 选择今天或之后的日期；如果选择今天，只能选当前时间之后尚未开始的时间段。
3. 选择 `08:00-20:00` 范围内的时间段。
4. 保持“库存不足时加入候补队列”勾选。
5. 点击“生成令牌”。
6. 点击“提交预约”。

预期：

- 页面显示一次性提交令牌。
- 预约提交成功。
- 返回 `RESERVED` 或 `WAITLIST`。
- 订单列表刷新。
- Redis 库存面板刷新。
- Dashboard 计数变化。
- 站内信出现预约或候补消息。

后端接口：

```text
POST /reservations/submit-token
POST /reservations
GET /reservations
GET /ops/redis/stock
GET /reservations/dashboard
GET /notifications
```

### 6. 取消预约

页面区域：我的预约

步骤：

1. 找到状态为“已预约”的订单。
2. 点击“取消”。

预期：

- 取消成功。
- 订单状态刷新。
- Redis/MySQL 库存恢复或候补用户被补位。
- 站内信出现取消消息。

后端接口：

```text
POST /reservations/{orderId}/cancel
```

### 6.1 取消候补

页面区域：我的预约 -> 候补队列

步骤：

1. 先用一个已满库存的时间段提交预约，并勾选“库存不足时加入候补队列”。
2. 进入“我的预约”页面下方的“候补队列”表格。
3. 找到状态为“候补中”的候补单。
4. 点击“取消候补”。

预期：

- 候补单状态变为“已取消”。
- 控制台候补数量减少。
- 通知中心出现候补取消消息。
- 不影响正式预约单库存，因为候补没有提前占库存。

后端接口：

```text
GET /reservations/waitlist
POST /reservations/waitlist/{waitlistId}/cancel
```

### 6.2 候补过期

页面区域：我的预约 / 控制台

规则：

- 候补日期早于今天会自动过期。
- 如果候补日期是今天，时间段开始时间已经到达或过去，也会自动过期。

预期：

- 再次打开“我的预约”或“控制台”时，过期候补不会继续显示为“候补中”。
- 过期候补状态为“已过期”。
- 取消预约触发候补补位前，会先跳过这些过期候补。

### 7. 签到

页面区域：我的预约

步骤：

1. 找到状态为“已预约”的订单。
2. 点击“签到”。

预期：

- 签到成功。
- 订单状态变为“已签到”。
- Dashboard 已签到数量增加。
- 站内信出现签到消息。

后端接口：

```text
POST /reservations/sign
```

### 8. 运维看板

页面区域：运维

预期：

- Redis 面板能看到项目 key 数量。
- RabbitMQ 面板能看到通知队列和死信队列。
- RabbitMQ 面板能看到可靠消息 Outbox 的 pending、sent、retrying、dead 数量。
- 站内信能看到 MQ 消费后的消息。

后端接口：

```text
GET /ops/redis/overview
GET /ops/mq/overview
GET /ops/mq/outbox
POST /ops/mq/outbox/publish
GET /notifications
```

### 9. 问题反馈工单

页面区域：问题反馈

学生步骤：

1. 使用学生账号登录。
2. 打开“问题反馈”。
3. 填写标题和问题描述。
4. 点击“提交反馈”。

学生预期：

- 反馈列表出现新工单。
- 状态为“待处理”。
- 管理员账号通知中心收到“新的学生反馈”。

管理员步骤：

1. 使用管理员账号登录。
2. 打开“问题反馈”。
3. 点击反馈列表中的“处理”。
4. 填写回复内容并点击“回复学生”。

管理员预期：

- 工单状态变为“已回复”。
- 回复内容显示在反馈列表。
- 学生账号通知中心收到“管理员已回复反馈”。

关闭步骤：

1. 学生或管理员点击“关闭”。
2. 刷新反馈列表。

关闭预期：

- 工单状态变为“已关闭”。
- 已关闭工单不能继续回复。

后端接口：

```text
POST /feedbacks
GET /feedbacks
POST /feedbacks/{id}/reply
POST /feedbacks/{id}/close
```

### 10. 接口审计与 TraceId

页面区域：联调日志

步骤：

1. 用管理员账号登录。
2. 进入控制台、预约总览、中间件运维等页面触发多个后端接口。
3. 点击“联调日志”。

预期：

- 页面左侧显示前端操作日志。
- 页面右侧显示后端接口审计日志。
- 每条审计日志包含请求方法、URI、状态码、耗时、角色和 traceId。
- 接口响应头包含 `X-Trace-Id`。

后端接口：

```text
GET /ops/audit/logs
GET /ops/audit/overview
```

## 当前覆盖结论

当前前端覆盖了：

- 注册手机号格式校验。
- 登录与 Token 维持。
- 教室查询。
- 智能推荐回填预约。
- 一次性提交令牌。
- 预约提交。
- Redis/MySQL 库存核对。
- 取消预约。
- 签到。
- RabbitMQ 通知消费结果查询。
- RabbitMQ 可靠消息 Outbox 状态查询和补偿投递。
- 后端接口审计日志和 traceId 查询。
- Dashboard 指标刷新。
