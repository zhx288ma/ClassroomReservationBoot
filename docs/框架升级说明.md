# Java 17, Spring Boot 4 and Agent Runtime

## Runtime baseline

- Java target: 17. The project can be started with a newer compatible JDK, but the Maven compiler emits Java 17 bytecode.
- Spring Boot: 4.1.1.
- MyBatis Spring Boot Starter: 4.0.0.
- Docker build/runtime: Eclipse Temurin 17.

## Agent integration boundary

The reservation transaction remains independent from every AI dependency. AI can only interpret a request, retrieve policy knowledge and prepare a reservation draft. The user still confirms the draft, and the existing Redis Lua plus MySQL transaction path decides whether a reservation succeeds.

### LangChain4j

`LangChainAgentConfig` provides an optional LangChain4j `ChatModel`. When enabled, it selects a fixed intent only: search availability, create a draft, retrieve rules, show the user's reservations or show administrator statistics. Tool execution and authorization stay in `AgentServiceImpl`.

It is disabled by default. To enable an OpenAI-compatible provider in PowerShell:

```powershell
$env:CLASSROOM_AGENT_LANGCHAIN_ENABLED = "true"
$env:CLASSROOM_AGENT_LANGCHAIN_API_KEY = "your-api-key"
$env:CLASSROOM_AGENT_LANGCHAIN_BASE_URL = "https://api.openai.com/v1"
$env:CLASSROOM_AGENT_LANGCHAIN_MODEL = "gpt-4.1-mini"
```

If these variables are absent, the deterministic intent parser is used. This is deliberate: application startup and the core reservation service do not depend on a paid model endpoint.

### Spring AI

Spring AI is included as the standard embedding and Qdrant vector-store abstraction. `AgentEmbeddingService` first uses a Spring AI `EmbeddingModel` when one is configured; otherwise it uses the existing compatible embedding adapter; if neither is configured, it falls back to local lexical retrieval.

This makes the document pipeline progressive:

`PDF / Markdown / TXT upload -> PDFBox text extraction -> chunking -> MySQL persistence -> optional embedding -> optional Qdrant semantic retrieval -> lexical fallback`

No vector provider is enabled by default, so PDF upload and rule retrieval still work without an API key or an Ollama download.

## Startup checks

```powershell
java -version
mvn -DskipTests clean compile
mvn spring-boot:run
```

For Docker image validation:

```powershell
docker compose build app
```

The Qdrant and model configuration are optional. Do not enable `CLASSROOM_AGENT_LANGCHAIN_ENABLED` until an API key has been configured.
